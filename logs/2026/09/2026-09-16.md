서비스의 1차 목표를 **감으로 익힌 일본어를 문자·어휘·문법과 연결해, 이후 자격증 학습에 들어갈 수 있는 기초 실력을 만드는 것**으로 구체화했다. 자격증 취득은 장기 목표로 두되 현재 단계에서는 특정 급수와 시험일을 기준으로 삼지 않는다. 초기 외부 인터뷰를 필수 단계로 두기보다 실제 학습 과정과 반복적으로 겪은 불편을 핵심 리서치 자료로 활용하기로 했다.

### Observed Problem

- 듣기와 회화는 실제 상황에서 활용할 수 있지만, 문자 인식과 정확한 해석 능력이 상대적으로 부족하다.
- 일본어 가사를 소리와 분위기로 이해해도 실제 문장 해석은 예상과 반대가 될 수 있다.
- 히라가나를 읽을 수 있지만 실시간 속도를 따라가기 어려워 한글 발음에 의존한다.
- 일본어 텍스트를 만나면 직접 읽기보다 전체 번역을 먼저 사용해 원문이 학습으로 남지 않는다.
- 준비한 질문은 말할 수 있지만 예상하지 못한 긴 답변에서는 세부 정보를 놓치기 쉽다.

핵심 문제를 **일본어를 전혀 모르는 상태가 아니라, 귀와 입에 축적된 일본어가 문자·문법·정확한 의미로 전환되지 않은 상태**로 정의했다.

- 한글 발음은 정답이 아니라 일본어 문자로 넘어가기 위한 임시 힌트로 사용한다.

- 예상한 의미와 실제 의미의 차이를 보여주고, 해석이 달라진 원인을 학습시킨다.
- 실제 상황에서 수집한 표현을 자격증 어휘·한자·문법 학습과 연결한다.

## Product Strategy & MVP Planning

최종 문제 정의를 기준으로 해결책 가설을 평가하고, V1을 **HEARD + 최소한의 COMPARE**로 좁혔다. Product Strategy와 기능 우선순위는 `docs/PRODUCT-STRATEGY.md`, 구체적인 첫 버전 범위는 `docs/MVP.md`에 기록했다.

### Value Proposition

> 귀로는 아는 일본어를, 다음에는 직접 읽을 수 있게.

### V1 Decision

```text
한글 발음 입력
→ 선택적으로 맥락·예상 의미 추가
→ 일본어 후보 2~3개
→ 찾던 표현 선택
→ 표기·읽기·뜻·핵심 구조
→ 예상과 실제 의미 / 유사음 비교
→ 저장 또는 결과 피드백
```

- 한글 발음 검색만 제공하지 않고 후보 선택과 오해 원인 확인을 핵심 가치로 둔다.
- 예상 의미 입력은 강제하지 않고 프로토타입에서 입력 부담과 학습 가치를 함께 검증한다.
- AI가 불확실한 결과를 단정하지 않도록 후보·확신 수준·추가 맥락 요청 상태를 둔다.
- LocalStorage 저장과 간단한 결과 피드백까지를 하나의 완결된 V1 흐름으로 본다.
- READ·WRITE·LISTEN·본격 REVIEW·상용 콘텐츠 DB·JLPT 커리큘럼은 V1에서 제외한다.

### Initial Acceptance Targets

- 실제 개인 사례 최소 10개
- 목표 표현이 상위 3개 후보에 포함되는 사례 10개 중 8개 이상
- 외부 검색 없이 후보를 선택하고 핵심 차이를 설명할 수 있는지 확인
- 저장한 표현을 3~7일 후 다시 보았을 때 재인식 여부 기록
- 수치는 검증 전의 초기 합격선 가설로 두고 테스트 결과에 따라 수정

## Original Song LISTEN Concept

실제 노래방에서 일본어 가사만 보고 노래를 따라가야 하는 상황을 저작권 안전성이 높은 자체 학습 콘텐츠로 재현하기 위해, AI를 보조 도구로 활용한 오리지널 일본어 노래 기반 LISTEN 모드를 후속 기능으로 정의했다.

### Flow

```text
자체 제작 일본어 노래의 특정 구간 듣기
→ 들린 일본어 가사 고르기
→ 가사의 뜻 고르기
→ 정답 표기·읽기·문법 확인
→ 저장 또는 다시 듣기
```

### Rights Decision

- AI 생성이라는 이유만으로 저작권 문제가 자동 해결된다고 가정하지 않는다.
- 상업 이용을 허용하는 도구·요금제만 사용한다.
- 가사는 직접 작성·수정하고, 특정 기존 곡·가수·목소리·스타일 모방을 피한다.
- 프롬프트·가사 수정본·생성일·도구 약관·라이선스 증빙을 보관한다.
- 배포 전 기존 곡과의 유사성을 검토한다.
- 이 기능은 V1 HEARD MVP가 아니라 후속 LISTEN Mode로 배치한다.

## Information Architecture & User Flow

Learning Design을 화면 구조와 정상·예외 흐름으로 전환해 `docs/IA-USER-FLOW.md`에 기록했다.

### IA Decision

- V1의 1차 내비게이션은 ‘홈’과 ‘저장 표현’ 두 개로 제한한다.
- 복습은 독립 탭이 아니라 저장 표현 안의 ‘복습하기’로 진입한다.
- WRITE·READ·LISTEN·프로필·설정·랭킹은 V1 내비게이션에서 제외한다.
- 홈→후보→결과→저장과 저장 표현→복습 설정→문제→피드백→완료 흐름을 정의했다.

### Key Flow Rules

- 후보가 하나여도 자동 정답 처리하지 않고 사용자가 확인한다.
- 낮은 확신은 숫자 확률 대신 ‘가능성 높음 / 맥락 필요’처럼 정성적으로 표시한다.
- 결과는 일본어 표기부터 보여주고 읽기·뜻·한국어 발음을 단계적으로 공개한다.
- 검색 실패 시 입력값을 보존하고 맥락 추가와 재입력을 제공한다.
- 동일한 표현은 중복 저장하지 않는다.
- 복습 문제 수는 사용자가 직접 선택한다.
- 복습 중 종료해도 완료한 문제의 기록만 저장하고 이탈을 막지 않는다.
- 오답은 강제 재도전 없이 정답·핵심 차이·선택 문법 설명으로 이어진다.

### Scope Decision

- 전역 내비게이션은 홈과 저장 표현으로 유지한다.

- 제품 구조는 `HEARD + PRACTICE + COMPARE + MINIMAL REVIEW`로 확장한다.

## Frequent Kanji Expression Content

V1 한자 학습 범위를 ‘기초·생활 한자 20자’에서 **실제로 자주 쓰는 한자 표현 20개와 자연스러운 예문**으로 수정했다. 상세 목록과 콘텐츠 원칙은 `docs/KANJI-CONTENT.md`에 기록했다.

### Decisions

- 한자 한 글자의 음독·훈독을 모두 암기하기보다 `今日`, `明日`, `私`, `君`, `心`, `胸`, `気持ち`처럼 실제 단어·표현 단위로 학습한다.
- 모든 표현은 짧고 자연스러운 문장과 함께 제공한다.
- 노래·일상 대화·여행에서 자주 접하고, 사용자가 소리로 먼저 알고 있을 가능성이 높은 표현을 우선한다.
- `心 / 胸 / 気持ち`, `私 / 僕 / 君`처럼 한국어 번역만으로 놓치기 쉬운 뉘앙스와 사용 관계를 함께 설명한다.
- `今日→きょう`, `明日→あした`, `昨日→きのう`처럼 글자별 읽기보다 단어 전체 읽기로 익혀야 하는 표현을 명시한다.
- 문제는 표기→읽기, 표기→뜻, 문맥 문장, 유사 의미 구분, 빈칸 채우기로 구성한다.

## Romanization Pronunciation Hint

읽기 정보의 보조 발음 표기를 한국어 음차에서 영문 로마자로 변경했다.

### Decisions

- 결과와 학습 문제에서는 일본어 표기와 히라가나 읽기를 우선한다.
- 히라가나 옆에 작은 `(발음 보기)` 버튼을 배치한다.
- 버튼을 누른 뒤에만 헵번식 영문 로마자 발음을 보여준다. 예: `今日 / きょう / kyō`.
- 로마자는 선택형 보조 힌트이며 기본 상태에서는 숨긴다.
- 한글 발음은 사용자가 소리를 검색할 때의 입력 방식으로 유지하되, 읽기 결과의 출력 힌트로는 사용하지 않는다.

## Kanji Table View More

자주 쓰는 한자 표현의 전체 V1 수량과 최초 노출 수량을 분리했다.

### Decisions

- V1 한자 표현 콘텐츠는 최소 40개와 각 예문으로 구성한다.
- 표에는 처음 20개만 노출한다.
- 표 하단의 `더 많은 한자 표현 보기` 텍스트 버튼을 누르면 기존 표 아래에 다음 20개를 추가한다.
- 총 40개가 표시되면 버튼을 숨긴다.
- 목록을 교체하거나 다른 페이지로 이동하지 않으며, 확장 시 스크롤 위치를 유지한다.
- 불러오기 실패 시 기존 20개는 그대로 유지하고 다시 시도를 제공한다.
