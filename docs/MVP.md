# MVP Scope

## 1. V1 Goal

> 사용자가 기억한 일본어 소리 하나를 정확한 표현으로 찾고, 왜 그렇게 해석되는지 이해한 뒤, 다음 인식을 위한 학습 항목으로 남길 수 있는지 검증한다.

V1은 기능 수보다 하나의 완결된 학습 경험을 우선합니다. 시험 대비 서비스나 종합 일본어 앱을 만들지 않고 **HEARD + 최소한의 COMPARE**에 집중합니다.

## 2. Core User Story

> 일본 콘텐츠나 실제 상황에서 들은 일본어 발음은 기억나지만 정확한 표기를 모를 때, 한글로 들리는 대로 입력해 가능한 표현을 비교하고 실제 표기와 의미를 이해한 뒤 다음에는 직접 알아보고 싶다.

## 3. Core Flow

```text
한글 발음 입력
→ 선택적으로 맥락·예상 의미 추가
→ 일본어 후보 2~3개
→ 찾던 표현 선택
→ 표기·읽기·뜻·핵심 구조
→ 예상과 실제 의미 / 유사음 비교
→ 저장 또는 결과 피드백
```

## 4. Must-have Features

### 4.1 한글 발음 입력

예: 카와라나이 모노

정확한 음차를 요구하지 않습니다. 입력이 너무 짧거나 모호하면 결과를 지어내지 않고 맥락을 요청합니다.

### 4.2 선택형 맥락

필수 입력으로 만들지 않습니다.

- 들은 곳: 노래·애니·대화·여행
- 앞뒤에 기억나는 단어
- 상황
- 사용자가 예상한 의미

### 4.3 일본어 후보

최대 2~3개를 제공합니다.

- 일본어 표기
- 히라가나 읽기
- 한 줄 의미
- 후보를 구분할 짧은 맥락
- 확신 수준

### 4.4 후보 선택

사용자가 찾던 표현을 직접 선택합니다. 어느 후보도 아니라면 맥락을 보완하거나 새로 검색할 수 있습니다.

### 4.5 Result Detail

- 일본어 표기
- 히라가나·필요한 후리가나
- 자연스러운 한국어 의미
- 핵심 단어와 원형
- 핵심 문법 또는 활용
- 사용 맥락 라벨

설명은 핵심 정보부터 보여주고 상세 정보는 펼쳐봅니다.

### 4.6 Compare

- 비슷하게 들리는 후보와 차이
- 사용자가 예상한 의미와 실제 의미의 차이
- 해석이 달라진 핵심 단어·문법

예상 의미를 입력하지 않은 경우 후보 간 차이만 보여줍니다.

### 4.7 Save

로그인 없이 LocalStorage 저장을 허용합니다.

저장 항목:

- 일본어 표기와 읽기
- 의미
- 처음 입력한 한글 발음
- 선택적인 출처·개인 메모
- 저장일

### 4.8 Feedback

- 찾던 표현이에요
- 찾던 표현이 아니에요

부정 피드백에서는 재입력 또는 맥락 추가로 이어집니다.

## 5. Required States

- Initial
- Typing
- Optional Context Open
- Loading
- Multiple Candidates
- Candidate Selected
- Low Confidence
- Need More Context
- No Result
- Result Detail
- Saved
- Empty Saved List
- Error

## 6. AI Output Guardrails

- 입력 하나에 정답 하나가 있다고 가정하지 않는다.
- 후보 수를 2~3개로 제한하고 차이를 설명한다.
- 낮은 확신을 명시하고 필요한 맥락을 요청한다.
- 문법 설명은 짧고 학습자 친화적으로 제공한다.
- 검증되지 않은 사용 빈도를 숫자로 표시하지 않는다.
- 상용 가사·음원·영상의 전문을 저장하거나 재배포하지 않는다.
- 사용자가 제공한 짧은 표현과 자체 예문으로 학습 구조를 검증한다.

## 7. Should-have Experiments

- “나는 이런 뜻인 줄 알았어요” 입력
- 예상과 실제 의미의 차이 카드
- 한글 발음 힌트 접기·펼치기
- 저장 시 출처·메모

유용성과 입력 부담을 함께 확인하고 V1 구현 여부를 결정합니다.

## 8. Out of Scope

- WRITE·LISTEN 전체 모드
- READ 이미지·텍스트 가져오기
- 상용 J-POP 가사·음원·영상 DB와 노래방 싱크
- 음성 인식·자동 구간 추출
- 로그인·결제·소셜·추천
- 완성형 SRS
- JLPT 급수별 커리큘럼
- 고급 개인화와 통계

## 9. Acceptance Targets

검증 전의 초기 합격선 가설입니다.

- 실제 개인 사례 최소 10개
- 목표 표현이 상위 3개 후보에 포함되는 사례 10개 중 8개 이상
- 낮은 확신 사례를 단정하지 않고 표시
- 외부 검색 없이 후보를 선택하고 핵심 차이를 설명
- 저장 표현을 3~7일 후 다시 보았을 때 재인식 여부 기록
- 새로운 표현에서 같은 흐름을 다시 사용하는지 확인

함께 기록할 지표:

- 결과까지 걸린 시간
- 재입력·실패 비율
- 긍정/부정 피드백
- 저장률과 저장 이유
- 한글 발음 힌트 사용 여부
- 중단 지점
