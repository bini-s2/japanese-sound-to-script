# Product Strategy & MVP Planning

## 1. Product Vision

> 귀로는 아는 일본어를, 다음에는 직접 읽을 수 있게.

**Japanese Sound to Script**는 일본 콘텐츠와 실제 경험을 통해 먼저 쌓인 듣기·회화 감각을 일본어 표기·어휘·문법·정확한 의미로 연결하는 학습 서비스입니다.

자격증 합격을 당장의 제품 기준으로 삼지 않습니다. 듣기·문맥 감각이 앞선 학습자가 자신의 강점을 발판으로 가타카나·한자·회화·정확한 읽기를 더 빠르고 재미있게 익히고, 이후 자격증 학습을 시작할 기반을 만드는 것이 목표입니다.

## 2. Goal Hierarchy

### Long-term Goal

- 일본어 자격증 취득
- 일본어 콘텐츠와 실전 상황을 번역기 없이 이해하는 범위 확대

### Current Learning Goal

- 익숙한 소리를 히라가나·가타카나·한자 표기와 연결
- 감으로 이해한 의미와 실제 문장 의미의 차이를 설명
- 저장한 표현을 다시 만났을 때 직접 읽고 알아보기
- 강한 듣기·문맥 감각을 활용해 가타카나·한자·회화·정확한 읽기를 더 빠르고 흥미롭게 학습
- 자격증 학습에 들어갈 수 있는 문자·어휘·문법 기반 형성

### V1 Product Goal

> 사용자가 기억한 일본어 소리 하나를 정확한 표현으로 찾고, 왜 그렇게 해석되는지 이해한 뒤 저장하고, 최소한의 복습으로 다시 알아볼 수 있는지 검증한다.

## 3. Primary User

일본 콘텐츠와 실전 경험으로 듣기·회화 감각을 먼저 익혔지만, 히라가나 읽기 자동화·가타카나·한자·정확한 문장 해석이 뒤처진 한국인 학습자.

초기 사용자 1호는 프로젝트 제작자 본인입니다. 외부 사용자 확장 전 실제 검색 사례와 학습 변화를 개인 베타로 관찰합니다.

## 4. Value Proposition

### Primary Promise

> 귀로는 아는 일본어를, 다음에는 직접 읽을 수 있게.

### Functional Value

- 한글로 기억한 소리에서 가능한 일본어 표현을 찾는다.
- 불확실한 경우 여러 후보와 구분 근거를 확인한다.
- 실제 표기·읽기·뜻·핵심 문법을 짧게 연결한다.
- 내가 예상한 의미와 실제 의미가 왜 달랐는지 확인한다.
- 다시 만났을 때 직접 알아볼 표현으로 저장한다.

### Emotional Value

- 일본어를 전혀 모르는 초보자로 취급받지 않는다.
- 이미 쌓아온 듣기와 회화 감각을 학습 자산으로 인정받는다.
- 번역기에 맡기고 끝나는 대신 “내가 알게 되었다”는 감각을 얻는다.

## 5. Primary Use Case

> 콘텐츠나 실제 상황에서 일본어 표현을 들었지만 정확한 표기를 모른다. 기억나는 한글 발음과 선택적인 맥락을 입력하고, 2~3개의 일본어 후보 중 찾던 표현을 고른다. 결과에서 표기·읽기·뜻·핵심 구조와 혼동 이유를 확인한 뒤 개인 표현장에 저장한다.

## 6. V1 Core Loop

```text
기억한 한글 발음 입력
→ 선택적으로 맥락·예상 의미 추가
→ 일본어 후보 2~3개 확인
→ 찾던 표현 선택
→ 표기·읽기·뜻·핵심 구조 확인
→ 예상과 실제 의미 / 유사음 비교
→ 저장 또는 결과 피드백
→ 3~7일 후 최소 복습
```

V1은 **HEARD + COMPARE + MINIMAL REVIEW**로 구성합니다.

- **HEARD:** 기억한 소리에서 실제 일본어 표현을 찾는다.
- **COMPARE:** 모든 결과에서 후보 간 차이를 보여준다. 예상 의미를 입력한 경우에는 사용자가 오해한 이유까지 설명한다.
- **SAVE:** 다음 인식을 위한 개인 학습 항목으로 남긴다.
- **MINIMAL REVIEW:** 완성형 SRS 없이 저장한 표현을 세 가지 짧은 방식으로 다시 알아본다.

## 7. Product Principles

1. **소리에서 시작한다.** 사용자가 이미 가진 청각 기억을 첫 입력으로 인정한다.
2. **불확실성을 숨기지 않는다.** 하나의 정답을 지어내지 않고 후보와 확신 수준을 보여준다.
3. **번역에서 끝내지 않는다.** 표기·읽기·핵심 구조를 함께 연결한다.
4. **예측 오류를 학습 자산으로 만든다.** 예상 의미와 실제 의미의 차이를 비난 없이 설명한다.
5. **한글 발음은 임시 다리로 쓴다.** 결과에서는 일본어 표기를 중심에 두고 점차 힌트 의존을 낮춘다.
6. **결과를 짧게 유지한다.** 필요한 설명만 먼저 보여주고 상세 정보는 펼쳐본다.
7. **실제 관심 표현을 우선한다.** 정해진 진도보다 사용자가 방금 궁금했던 표현을 학습 대상으로 삼는다.

## 8. Feature Priority

### Must — V1에 반드시 포함

- 한글 발음 입력
- 선택형 맥락 입력: 노래 가사·식당 주문·지하철에서 길 묻기 등 출처·상황·앞뒤 단어
- 가능한 일본어 후보 2~3개와 확신 수준
- 후보별 일본어 표기·히라가나·간단한 의미
- 사용자의 후보 선택
- 결과 상세: 표기·읽기·자연스러운 한국어 의미
- 핵심 단어·원형·문법 또는 활용 설명
- 비슷하게 들리는 후보와 차이
- 예상 의미를 입력한 경우 실제 의미와 달라진 핵심 단어·문법 설명
- 상황이 제시된 검증 문제와 신뢰할 수 있는 사전·문법 근거로 테스트 정답 확인
- 개인 표현장 로컬 저장·목록
- 저장 목록에서 한국어 뜻을 가리고 일본어 표현 알아보기
- 일본어 표현을 보고 뜻을 고르는 1문제
- 한국어 발음 힌트를 가리고 일본어 표기 읽기·재인식하기
- “찾던 표현이에요 / 아니에요” 결과 피드백
- 낮은 확신·정보 부족·오류 상태

### Should — 프로토타입에서 함께 검증

- “나는 이런 뜻인 줄 알았어요” 선택 입력
- 저장 시 출처·개인 메모 남기기

입력 부담과 정보 과부하 가능성이 있어 사용성 테스트로 V1 포함 여부를 결정합니다.

### Could — V1 이후 후보

- 텍스트·이미지에서 표현을 가져오는 READ
- 가타카나·한자가 섞인 노래방 가사에 읽기·한국어 발음 힌트를 제공하는 READ 확장
- 자체 제작 일본어 노래를 활용한 LISTEN 퀴즈: 특정 구간 듣기→일본어 가사 고르기→뜻 고르기→표기·문법 확인
- 가타카나·한자별 개인 오답 모음
- 계정 기반 동기화
- 외부 사전·코퍼스 근거 링크

### Won't — V1에서 제외

- WRITE 전체 모드
- LISTEN 전체 모드
- 상용 J-POP 가사·음원·영상 데이터베이스
- 노래방 싱크 가사
- 음성 인식과 자동 구간 추출
- 전체 커리큘럼과 JLPT 급수별 진도
- 완성형 SRS·장기 복습 알고리즘
- 로그인·결제·추천·소셜 기능

## 9. Why This Scope

V1이 검증할 핵심은 “많은 일본어 기능을 제공할 수 있는가”가 아닙니다.

1. 한글로 기억한 소리에서 찾던 표현을 충분히 정확하게 발견할 수 있는가?
2. 사용자가 후보 차이와 자신의 오해 지점을 이해할 수 있는가?
3. 그 결과가 번역 확인으로 끝나지 않고 다음 읽기에 남는가?

READ·WRITE·LISTEN·완성형 SRS를 동시에 만들면 어느 기능이 변화를 만들었는지 알기 어렵습니다. 가장 자주 발생한 실제 행동인 **들은 표현을 찾는 순간**부터 검증하되, 검색이 학습으로 남는지는 세 가지 최소 복습으로 확인합니다. 노래방에서 한국어 발음을 찾는 문제는 후속 READ의 대표 사용 사례로 보존합니다.

## 10. V1 Acceptance Targets

아래 수치는 검증 전의 **초기 합격선 가설**이며 KPI로 확정하지 않습니다.

### Retrieval

- 노래 가사·식당 주문·지하철에서 길 묻기 등 상황이 명시된 실제 개인 사례 최소 10개로 테스트
- 정확한 음차·일부 음절 누락·유사음·활용형·문맥 의존 표현을 섞어 테스트
- 목표 표현이 상위 3개 후보에 포함되는 사례 10개 중 8개 이상
- 확신이 낮을 때 단정하지 않고 추가 맥락 또는 불확실성을 표시

### Comprehension

- 외부 번역기나 검색 없이 후보를 선택할 수 있는가
- 결과를 본 뒤 “왜 내가 다르게 이해했는지” 본인의 말로 설명할 수 있는가
- 어떤 정보가 선택과 이해에 기여했는지 기록

### Learning

- 저장 목록에서 뜻을 가렸을 때 일본어 표현을 알아보는가
- 일본어 표현을 보고 뜻을 고르는 1문제를 맞히는가
- 한국어 발음 힌트 없이 일본어 표기를 읽고 재인식하는가
- 한글 발음 힌트를 보지 않고 알아본 표현이 늘어나는가
- 새로운 표현에서도 같은 흐름을 다시 사용하는가

### UX Signals

- 입력부터 결과 확인까지 걸린 시간
- 후보 선택 실패·재입력 비율
- 결과 피드백의 긍정/부정
- 저장률과 저장 이유
- 중단 지점과 정보 과부하 여부

## 11. Risks & Guardrails

| Risk | Guardrail |
|---|---|
| AI가 틀린 일본어를 자신 있게 제시 | 여러 후보, 확신 수준, 정보 부족 상태 제공 |
| 한글 발음이 오히려 의존을 강화 | 결과의 중심은 일본어 표기, 발음 힌트는 접을 수 있게 설계 |
| 설명이 많아 검색 흐름이 끊김 | 핵심 결과 우선, 문법·비교는 점진적으로 공개 |
| 사용자가 정답 후보를 판단할 수 없음 | 맥락·예상 의미를 선택적으로 받고 후보별 차이를 한 줄로 제공 |
| 번역 확인으로 끝나 학습이 남지 않음 | 비교·저장·추후 재인식 측정을 하나의 루프로 설계 |
| 저작권 콘텐츠에 과도하게 의존 | V1은 자체 예문·사용자 입력으로 검증하고, LISTEN은 권리를 확보한 자체 제작 곡만 사용 |
| AI 음악을 사용하면 자동으로 권리가 해결된다고 오해 | 상업 이용이 허용된 도구·요금제 확인, 기존 곡·가수·캐릭터 모방 금지, 가사 직접 작성·수정, 생성 기록과 약관 보관, 배포 전 유사성 검토 |

## 12. Delivery Sequence

1. 실제 개인 사례 10개 수집
2. 후보 생성과 결과 정보 구조를 수동 또는 AI 프롬프트로 검증
3. 핵심 User Flow와 상태 정의
4. Low-fi Prototype 제작
5. 개인 Task Test
6. 수정 후 작동하는 웹 MVP 구현
7. 3~7일 후 세 가지 최소 복습 테스트
8. 프로토타입에서 비슷한 학습자 3~5명에게 문제·사용성 검증
9. 결과에 따라 READ와 완성형 REVIEW 확장 여부 결정
