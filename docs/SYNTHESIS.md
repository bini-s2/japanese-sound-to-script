## 3. Affinity Clusters

### A. Sound is ahead of script

- 소리와 표현은 익숙하지만 일본어 표기를 보면 바로 연결되지 않는다.
- 히라가나는 천천히 읽을 수 있으나 실시간 읽기에는 부족하다.
- 가타카나와 한자가 등장하면 읽기 흐름이 크게 끊긴다.
- 한글 발음은 일본어 문자를 읽기 위한 임시 발판으로 사용된다.

### B. Gist is ahead of precision

- 아는 단어, 목소리, 멜로디, 상황으로 전체 뉘앙스를 빠르게 추론한다.
- 핵심 숫자나 익숙한 표현은 알아들을 수 있다.
- 부정·반전·접속·활용형을 놓치면 실제 의미가 예상과 달라진다.
- ‘대충 이해함’과 ‘정확히 설명할 수 있음’ 사이에 차이가 있다.

### C. Translation solves the task, not the learning

- 텍스트를 만나면 직접 읽기보다 전체 번역을 먼저 사용한다.
- 번역기는 현재 상황을 빠르게 해결하지만 원문을 다시 알아볼 수 있게 만들지는 않는다.
- 정답 번역만 보면 처음에 왜 다르게 이해했는지 남지 않는다.

### D. Prepared output is easier than unpredictable input

- 익숙한 상황의 질문과 짧은 회화는 사용할 수 있다.
- 상대방의 대답이 길거나 예상 밖의 표현을 쓰면 세부 정보를 놓친다.
- 회화 표현 추가보다 다양한 응답을 분해해 듣는 연습이 필요하다.

### E. Personal relevance creates motivation, review volume creates friction

- 실제로 궁금했던 노래·대화·문장은 기억과 동기를 만든다.
- 이미 아는 내용을 처음부터 반복하는 초급 커리큘럼은 비효율적으로 느껴질 수 있다.
- 카드와 복습량이 과도해지면 관심 기반 학습도 다시 숙제가 된다.

## 4. Core Insights

### Insight 1 — The learner is not empty

사용자는 일본어를 처음 접하는 상태가 아니다. 귀와 입에는 이미 상당한 표현과 문맥 감각이 축적되어 있다. 제품은 처음부터 가르치기보다 이미 가진 지식을 발견하고 문자에 연결해야 한다.

### Insight 2 — Recognition and exact understanding are different

익숙하게 들린다는 사실은 정확히 이해했다는 뜻이 아니다. 학습은 정답을 보여주는 것보다 사용자의 첫 해석과 실제 문장이 갈라진 지점을 드러내야 한다.

### Insight 3 — Korean pronunciation is scaffolding

한글 발음은 제거해야 할 잘못된 습관이 아니라 일본어 문자로 넘어가기 위한 임시 발판이다. 다만 계속 노출하면 일본어 문자 자동화를 방해하므로 점진적으로 줄여야 한다.

### Insight 4 — Translation should become a learning trigger

번역기를 금지하면 즉시성이라는 사용자 가치를 잃는다. 대신 번역 결과를 보기 전후에 읽기·어절·문법·예상 차이를 짧게 확인하게 만들어야 한다.

### Insight 5 — The moment of curiosity is the best entry point

정해진 커리큘럼보다 방금 들었거나 본 표현은 개인적 맥락이 있어 기억에 남는다. 제품은 이 순간을 놓치지 않고 가장 적은 단계로 저장과 회상까지 연결해야 한다.

### Insight 6 — The product must remain smaller than the study task

경쟁 서비스의 복습 부담과 도구 분산을 반복하지 않으려면, 설명·카드·알림을 늘리기보다 한 표현을 정확히 이해하고 다시 알아보는 짧은 루프에 집중해야 한다.

## 5. Target User

### Primary Target

> 일본 콘텐츠와 실전 경험을 통해 듣기·회화 감각을 먼저 익혔지만, 히라가나 읽기 자동화·가타카나·한자·정확한 문장 해석이 뒤처진 한국인 학습자

### Behavioral Characteristics

- 일본어를 들으면 아는 단어와 상황으로 의미를 어느 정도 추론한다.
- 기본적인 히라가나 또는 익숙한 회화 표현을 알고 있다.
- 일본어 표기보다 한국어 음차를 먼저 기억한다.
- 텍스트를 만나면 사전보다 번역기를 빠르게 사용한다.
- 콘텐츠 속 표현을 배우고 싶지만 기초 커리큘럼을 처음부터 반복하고 싶지는 않다.
- 자격증은 장기 목표일 수 있으나 당장은 문자·정확한 이해의 기반이 필요하다.

### Not the Primary Target

- 일본어를 처음 접해 소리·기초 표현·문자 모두 낯선 완전 초보자
- 일본어 원문을 빠르게 읽고 대부분의 문법을 정확히 해석하는 고급 학습자
- 단기간에 특정 급수 합격만을 목표로 문제 풀이와 점수 관리가 필요한 수험생

## 6. Needs & Pain Points

| Need | Current behavior | Pain |
| --- | --- | --- |
| 들은 표현의 정확한 표기 확인 | 한국어 발음으로 검색하거나 포기 | 표기가 없으면 검색 자체가 어렵다. |
| 문자와 소리 연결 | 한글 발음을 계속 참고 | 일본어 문자가 자동화되지 않는다. |
| 정확한 의미 확인 | 전체 번역 결과 확인 | 왜 예상과 달랐는지 알 수 없다. |
| 모르는 부분만 학습 | 여러 사전·문법·카드 도구 이동 | 흐름이 끊기고 기록이 분산된다. |

## 7. Jobs To Be Done

### Main JTBD

> 일본 콘텐츠나 실제 상황에서 익숙한 일본어를 듣거나 보았을 때, 흐름을 오래 끊지 않고 정확한 표기와 의미를 확인하고 내가 잘못 이해한 지점을 학습으로 남겨, 다음에는 한글 발음이나 전체 번역 없이 알아보고 싶다.

### Functional Jobs

- 한국어로 기억한 발음에서 가능한 일본어 표현을 찾는다.
- 여러 후보를 문맥과 의미로 비교한다.
- 표기·읽기·활용·핵심 문법을 한곳에서 확인한다.
- 예상한 의미와 실제 의미의 차이를 이해한다.
- 개인적으로 궁금했던 표현과 오답만 저장하고 다시 회상한다.

### Emotional Jobs

- 이미 알고 있는 일본어 능력을 무시당하지 않고 싶다.
- 문자를 보는 순간 완전 초보자가 된 듯한 답답함을 줄이고 싶다.
- 좋아하는 콘텐츠를 공부 숙제로 바꾸지 않으면서도 실력이 쌓이는 느낌을 얻고 싶다.

## 8. Final Problem Statement

> 일본 콘텐츠와 실전 경험으로 듣기·회화 감각을 먼저 쌓은 한국인 학습자는 일본어를 소리와 문맥으로는 알아듣지만, 이를 실제 표기·문법·정확한 의미로 빠르게 연결하지 못한다. 그래서 한글 발음과 전체 번역에 반복적으로 의존하고, 당장의 상황은 해결해도 그 표현이 자신의 읽기 능력으로 남지 않는다. 이들에게는 이미 아는 소리에서 시작해 오해한 지점을 확인하고, 다음에는 직접 읽고 알아보게 만드는 짧은 학습 연결 과정이 필요하다.

## 9. Opportunity Statement

> 사용자가 방금 들었거나 본 일본어를 즉시 해결하는 검색·번역 경험과, 다음에는 스스로 알아보게 만드는 학습 경험 사이를 연결한다.

## 10. How Might We

- 어떻게 하면 일본어 표기를 모르는 사용자가 한국어로 기억한 소리만으로 올바른 후보를 찾을 수 있을까?
- 어떻게 하면 정답을 바로 보여주면서도 사용자가 직접 문자와 의미를 연결하게 할 수 있을까?
- 어떻게 하면 한글 발음을 유용한 힌트로 쓰되 의존하지 않게 할 수 있을까?
- 어떻게 하면 사용자의 첫 해석과 실제 의미의 차이를 부담 없이 발견하게 할 수 있을까?
- 어떻게 하면 실제로 궁금했던 한 표현을 최소한의 조작으로 저장하고 다시 알아보게 할 수 있을까?
- 어떻게 하면 학습 효과를 만들면서도 콘텐츠 감상과 실제 상황의 흐름을 방해하지 않을 수 있을까?

## 11. Design Principles

1. **Start from known sound** — 이미 알고 있는 소리와 맥락에서 시작한다.
2. **Show uncertainty** — 확신이 낮을 때 하나의 정답처럼 단정하지 않는다.
3. **Reveal progressively** — 발음·어절·전체 의미를 한꺼번에 펼치지 않는다.
4. **Explain the gap** — 정답보다 사용자의 오해가 생긴 지점을 설명한다.
5. **Fade the scaffold** — 한글 발음과 번역 힌트를 점진적으로 줄인다.
6. **Keep capture lightweight** — 학습 기록이 콘텐츠 경험보다 무거워지지 않게 한다.
7. **Respect prior knowledge** — 이미 아는 내용은 반복시키지 않는다.
8. **Use rights-safe content** — 초기에는 자체 예문과 사용자 입력을 중심으로 검증한다.

## 12. Solution Hypotheses

아래는 문제 정의에서 도출한 해결책 가설이며 아직 검증된 기능이 아니다.

- HEARD: 한국어 음차→일본어 후보→표기·읽기·뜻·활용
- COMPARE: 내가 예상한 의미와 실제 의미의 차이 설명
- READ: 이미지·텍스트→발음 힌트→어절별 이해→전체 번역
- REVIEW: 실제로 궁금했던 표현과 오답의 재인식·회상
- Progressive Hint: 한글 발음→가나→한자의 단계적 전환

## 13. Validation Questions

- 한국어 음차 입력이 실제 상황에서 가장 빠른 시작 방식인가?
- 후보가 여러 개일 때 필요한 문맥을 부담 없이 입력할 수 있는가?
- 예상 의미를 먼저 남기는 과정이 유용한가, 아니면 검색을 방해하는가?
- 오해 원인 설명이 다음 재인식 정확도를 높이는가?
- 사용자는 저장한 표현을 실제로 다시 복습하는가?
- 한글 발음 힌트를 줄여도 읽기를 포기하지 않는가?
- 이 문제와 해결 방식이 사용자 1호 외의 학습자에게도 반복되는가?

## 14. Decision

Discovery 단계의 문제 정의를 확정한다. 다음 Product Planning 단계에서는 HEARD·COMPARE·READ·REVIEW를 모두 구현하지 않고, 최종 Problem Statement를 가장 적은 기능으로 검증할 MVP를 선택한다.
